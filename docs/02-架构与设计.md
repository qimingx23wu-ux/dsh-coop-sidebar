# 02 · 架构与设计

> 规划/执行过程组产物：技术方案、关键决策记录（ADR 风格）、数据流。

## 1. 总体架构：双半身插件

```
┌──────────────────────────── 浏览器（客户端半身 lib/client.js） ───────────────────────────┐
│  __ModuleLoader__ bundle                                                                   │
│  ├─ ctx.remote.$mount({package:'coop-sidebar', descriptors:[overview, explain]})           │
│  │      → 挂载远程命名空间 coopSidebar                                                     │
│  ├─ ctx.slots.inject('shell.overlay', …) → 注册可收缩侧边栏 UI                             │
│  └─ 组件：术语雷达 / 过程透明 / 协作之道 + 输入聚焦自动收起                                  │
└───────────────┬────────────────────────────────────────────────────────────────────────────┘
                │ Client→Host RPC（Typert 远程调用，JSON）
┌───────────────▼──────────────────────────── DSH 进程（宿主半身 lib/index.js） ────────────┐
│  CoopSidebarService extends TypertRemoteService (key: coopSidebar)                         │
│  ├─ overview(args)  → sessionQuery.readSurface → 术语检测 + 工具活动 + 权限快照             │
│  ├─ explain(args)   → 内置词库秒出 ｜ llm.stream 按需生成 5 段式解释                        │
│  └─ ctx.typert.register({invocations:[overview, explain]}) → 网关路由                        │
└────────────────────────────────────────────────────────────────────────────────────────────┘
```

## 2. 平台能力选型（关键决策）

| 决策点 | 方案 | 理由 |
|---|---|---|
| UI 位置 | `shell.overlay` 槽位（可加式，id `coop.sidebar`） | 替换风险 none，不遮蔽现有 UI；frame 级浮动层适合常驻侧边栏 |
| 术语检测 | 词库正则匹配（36 词双语别名，英文 `\b` 词边界） | 确定性、零模型成本；误报可控 |
| 解释生成 | 双通道：词库秒出 → 未收录/追问走 `llm.stream` | 成本控制 + 小白友好 |
| 会话数据 | `sessionQuery.readSurface(sessionId)` | live-preferred，读取真实模型表面事件 |
| 工具活动 | 事件流关联：assistant 消息 `tool-call` + `tool/result` 按 callId 配对 | 真实状态（运行中/完成/失败） |
| 权限快照 | `sandboxPolicy.defaultMode/overrideOf` + `approval.overrideOf` | 真实运行时值 |
| **Client→Host RPC** | Typert 远程服务：宿主 `TypertRemoteService`+`typert.register`；客户端 `$mount` 挂载命名空间 | 静态插件标准通信；`src-json` codec 免 schema 手写描述符 |
| 客户端 bundle | 手写 `__ModuleLoader__.load`（CJS 工厂，仅 require react） | 与官方客户端插件同构，无构建管线依赖 |

## 3. ADR：动态插件 → 静态部署插件（v0.2.0）

- **背景**：动态插件（cordis_define/run）按平台设计**不跨进程存活**；DSH 进程重启后 `coop-1` 全部定义丢失，侧边栏消失。
- **备选**：A) 继续动态插件，重启后手动重建（治标）；B) 静态部署插件（治本）。
- **决策**：B。注册进 web profile 宿主组合（`cordis.patch.yml` insert 行 + pnpm workspace 链接），随 DSH 启动自动加载。
- **后果**：持久化达成；代价是客户端须走静态 bundle + Typert 远程协议（协议风险已用冒烟测试对冲）。

## 4. 数据流

### overview（客户端每 5 秒轮询）
```
useSessions().current (sessionId)
  → rpc.overview({sessionId})
  → host: readSurface → extract(events.slice(-200))
      ├─ detectTerms(texts) → [{term, category}]
      ├─ buildActivity(toolCalls, toolResults) → [{name, status, time}]
      └─ collectPolicy → {sandboxDefault, sandboxOverride?, approvalOverride?}
  → 客户端渲染三个页签
```

### explain（用户点击术语/追问）
```
openTerm(term) → rpc.explain({sessionId, term, question})
  → host: 词库命中且无追问 → 直接返回词条（source:'glossary'）
  → 否则: 最近40事件文本(≤2000字)作为任务背景 → llm.stream(JSON 结构化 prompt)
      → 解析失败兜底: 返回原文摘要（source:'model'）
  → 客户端渲染 5 段式 + 建议追问
```

## 5. 安全与边界设计

- 侧边栏**只读**会话文本用于检测，不写回、不落盘。
- 解释生成使用**当前会话已配置模型**（`agentDefaultModel.currentSelection()`），temperature 0.3。
- 权限信息「尽力而为」：服务缺失时优雅降级，不阻塞 UI。
- 模型不可用 → 自动降级为纯内置词库（所有未收录名词提示"模型不可用"）。
