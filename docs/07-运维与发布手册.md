# 07 · 运维与发布手册

> 收尾 + 运营：部署拓扑、发布流程、回滚、变更控制、健康检查。

## 1. 部署拓扑

```
~/.dsh/profiles/web/
├── cordis.patch.yml                  ← 宿主组合：- insert: coop-sidebar（挂载行）
├── pnpm-workspace.yaml               ← packages: ['.', 'plugins/*']
├── package.json                      ← dependencies: { "coop-sidebar": "workspace:*" }
├── node_modules/coop-sidebar → ../plugins/coop-sidebar   （pnpm workspace 软链）
└── plugins/coop-sidebar/
    ├── package.json                  ← dsh.client.platform: web（触发客户端 bundle 扫描）
    └── lib/
        ├── index.js                  ← 宿主半身（TypertRemoteService + typert.register）
        └── client.js                 ← 客户端 bundle（__ModuleLoader__ + $mount + slots）
```

服务端行为：`clientModules` 扫描 Loader 条目中声明 `dsh.client` 的包 → 服务 `/plugins/coop-sidebar/client.js` → 注入 `window.__DSH_BOOT__` 启动清单。

## 2. 发布流程（每次迭代必走）

```mermaid
flowchart LR
  A[变更请求<br/>三问评估] --> B[实施<br/>改 lib/ 下文件]
  B --> C[验证<br/>node --check + 冒烟]
  C --> D[升级版本号<br/>package.json + CHANGELOG + versions/]
  D --> E[发布<br/>客户端改动=硬刷新<br/>宿主改动=重启 dsh web]
  E --> F[用户验收<br/>docs/04 验收步骤]
  F --> G[归档<br/>README 状态更新]
```

**变更三问**：
1. 改哪端？（`lib/index.js`=宿主 → 需重启；`lib/client.js`=客户端 → 硬刷新即可）
2. 要不要重启 DSH？（凡宿主行/宿主代码变更 → 要）
3. 用户怎么拿到新代码？（客户端 → ⌘+Shift+R；宿主 → 重启后自动）

## 4. 回滚方案

| 场景 | 操作 |
|---|---|
| 客户端 bundle 出问题 | 还原 `lib/client.js` 到上一版本文件 → 硬刷新；版本号降级记录 |
| 宿主半身出问题 | 还原 `lib/index.js`；若需彻底禁用：删掉 `cordis.patch.yml` 中 `- insert:` 下的 coop-sidebar 行 → 重启 DSH |
| 整体回滚 | 删除 `plugins/coop-sidebar/` + 移除 patch 行 + 恢复 `pnpm-workspace.yaml`/`package.json` → 重启 |

## 5. 健康检查

```bash
# 1) bundle 可访问（应 200）
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:3080/plugins/coop-sidebar/client.js

# 2) boot manifest 含插件（应输出 coop-sidebar）
curl -s http://127.0.0.1:3080/ | grep -o "coop-sidebar" | head -1

# 3) 组合配置含宿主行
dsh --profile web --dump-config | grep -A2 "coop-sidebar"

# 4) 浏览器 Console 无 coop-sidebar 报错；侧边栏竖条可见
```

## 7. 词库热更新（v0.2.2+）

**机制**：内置词库（`lib/index.js` 的 `GLOSSARY`）是基线；`lib/glossary-extra.json` 是外部扩展词库，
宿主按文件 mtime 缓存，每次 `overview`/`explain` 调用时自动检测变更。

**加词步骤（无需重启、无需刷新）**：
1. 编辑 `~/.dsh/profiles/web/plugins/coop-sidebar/lib/glossary-extra.json`；
2. 在数组末尾追加词条，格式与现有条目一致：
```json
{ "term": "词条名（中英）", "aliases": ["别名1", "alias2"], "category": "分类",
  "summary": "一句话", "plain": "大白话", "example": "例子",
  "principle": "原理", "boundary": "边界", "followUps": ["追问1", "追问2"] }
```
3. 保存 → **5 秒内**侧边栏「术语雷达」自动出现该词（overview 轮询拉取）。

**注意事项**：
- 新增分类无需注册，词条里的 `category` 即分类名，会自动分组显示。
- 英文别名按词边界匹配（`\b`），避免子串误报；中文别名直接包含匹配。
- 误改 JSON 导致解析失败时，宿主自动降级为仅内置词库（侧边栏不崩），修复文件后自动恢复。
- 恢复出厂：清空该文件为 `[]` 即回到 36 词内置词库。
