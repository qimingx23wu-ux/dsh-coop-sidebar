# 00 · 项目章程（Project Charter）

> 启动过程组（Initiating）产物：回答「为什么做、谁参与、做到什么算成功」。

## 1. 项目背景与目的

用户在使用 DeepSeek Harness 让 Agent 执行自动化任务时，会遇到大量专业名词（Token、沙箱、审批、Agent Loop……），
因无法理解而产生不信任感；同时看不到 Agent 正在做什么，难以判断是否该介入。
本项目的目的是：**通过一个常驻侧边栏，把「专业名词」和「Agent 过程」翻译成小白能懂的语言，
提升人机协同的透明度、信任度与合作度。**

## 2. 项目目标（SMART）

- **S**（具体）：交付一个可收缩的右侧边栏，包含术语解释、过程透明、协作指引三块能力。
- **M**（可度量）：内置 ≥30 个术语词库；术语检测来自真实会话内容；每个术语提供 5 段式解释（总结/大白话/例子/原理/边界）并可继续追问。
- **A**（可实现）：基于 DSH 平台现有能力（slots / llm / sessionQuery / typert 远程机制）实现，无外部依赖。
- **R**（相关）：直接服务于用户「小白也能用 Agent 编排自动化」的目标。
- **T**（有时限）：当日完成首版可运行版本。

## 3. 范围

**包含（In Scope）**
- 右侧可收缩侧边栏 UI（`shell.overlay` 槽位，可加式，不替换现有 UI）
- 术语雷达：检测 + 解释 + 例子 + 原理 + 边界 + 追问
- 过程透明：会话状态、最近工具活动、权限/沙箱/审批状态、边界清单
- 协作之道：人机角色与能力指引
- 持久化部署（静态插件，重启不丢失）

**不包含（Out of Scope）**
- 修改主对话界面、替换任何既有 UI 区域
- 术语在对话原文中的高亮（列入 v0.3.0 候选）
- 多用户 / 多语言 / 团队共享词库（列入远期）

## 4. 干系人登记

| 干系人 | 角色 | 关注点 | 参与方式 |
|---|---|---|---|
| 用户（本机使用者） | 发起人 / 验收者 / 最终用户 | 易用性、透明、不遮挡输入 | 提需求、验收、反馈缺陷 |
| 开发者（本会话 Agent） | 开发 / 测试 / 运维（多角色合一） | 平台契约正确性、可维护性 | 实现、自测、部署 |

## 5. 成功标准（验收标准总纲）

1. 侧边栏可展开/收起，展开时不遮挡正在进行的输入（v0.2.1 起自动收起）。
2. 术语检测来自**真实会话内容**，点击术语 5 秒内出解释（词库内秒出）。
3. 过程透明页签展示**真实运行时数据**（工具活动/权限），非写死假数据。
4. 刷新页面、重启 DSH 后侧边栏仍存在（v0.2.0 起）。

## 7. 约束与假设

- **约束**：动态插件不跨进程存活（平台硬限制，已通过静态化规避）；web profile 的 HMR 被禁用（改动需硬刷新验证）；客户端远程命名空间由 `$mount` 挂载（描述符需与宿主一致）。
- **假设**：DSH 保持当前版本运行；`llm.stream` 接口可用（不可用时解释服务自动降级为纯词库，已有兜底）。
