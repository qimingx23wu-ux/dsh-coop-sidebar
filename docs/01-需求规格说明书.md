# 01 · 需求规格说明书（SRS）

> 规划过程组（Planning）产物：功能需求、验收标准、需求变更记录。
> 需求编号规则：`FR-功能` / `NFR-非功能` / `CR-变更`。

## 1. 功能需求

| 编号 | 需求 | 描述 | 验收标准 | 版本 |
|---|---|---|---|---|
| FR-01 | 可收缩侧边栏 | 主界面之外（右侧浮动）的可加式面板，可收起为细条 | 展开/收起切换正常；收起态显示术语数量角标；不替换/不遮蔽既有 UI | v0.1.1 |
| FR-02 | 术语检测 | 自动扫描当前会话最近内容中的专业名词 | 检测来源为真实会话文本（非假数据）；英文别名按词边界匹配防误报 | v0.1.1 |
| FR-03 | 术语解释 | 点击术语展示：一句话总结/大白话/例子/原理/边界/建议追问 | 词库内术语秒出；未收录术语由模型按任务背景生成 | v0.1.1 |
| FR-04 | 继续追问 | 在解释下方可输入问题或点建议追问 | 追问回答同样为 5 段式结构 | v0.1.1 |
| FR-05 | 过程透明 | 展示会话状态、最近工具活动、权限/沙箱/审批、边界清单 | 数据来自真实运行时（会话事件流、sandboxPolicy/approval 服务） | v0.1.1 |
| FR-06 | 协作之道 | 展示人在回路中的角色与需提升的能力 | 静态指引内容完整 | v0.1.1 |
| FR-07 | 持久化 | 刷新/重启后侧边栏仍在 | 静态部署；重启 DSH 后自动加载 | v0.2.0 |
| FR-08 | 输入自动收起 | 在输入框内输入时面板不遮挡 | 焦点进入 TEXTAREA/INPUT/contenteditable 时自动收起；面板自身输入框不触发 | v0.2.1 |

## 2. 非功能需求

| 编号 | 类别 | 要求 |
|---|---|---|
| NFR-01 | 性能 | 词库解释零模型成本秒出；轮询 5s 一次，单次读最近 ≤200 条会话事件 |
| NFR-02 | 成本 | 未收录名词才调用模型（temperature 0.3，maxTokens 800），防 token 浪费 |
| NFR-03 | 可维护性 | 词库与逻辑集中在宿主半身；客户端 bundle 无第三方依赖（仅 react） |
| NFR-04 | 可回滚 | 宿主行可一键移除（删 `cordis.patch.yml` 插入行）；版本按语义化递增 |
| NFR-05 | 隐私 | 不落盘任何会话数据；仅按需读取当前会话表面文本 |

## 3. 需求变更记录（CR）

| 编号 | 变更 | 来源 | 影响评估 | 决定 | 版本 |
|---|---|---|---|---|---|
| CR-01 | 增加「协作之道」页签，回答"人在 Agent 时代扮演什么角色" | 用户探索性问题 | 低成本：仅客户端加静态页签 | 纳入范围 | v0.1.1 |
| CR-02 | 侧边栏需持久化，不随进程重启丢失 | 用户反馈"刷新后没有了" | 高：需架构级重写（动态→静态） | 批准，升级为 v0.2.0 | v0.2.0 |
| CR-03 | 输入时侧边栏遮挡，需自动收缩 | 用户反馈 | 低：仅客户端一处改动，不动宿主，无需重启 | 批准 | v0.2.1 |

> 变更流程见 `docs/07-运维与发布手册.md`。
