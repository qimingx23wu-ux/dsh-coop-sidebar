# v0.2.3 · 修复"追问无响应、跳回原解释"

> 状态：✅ 代码就绪，**需重启 DSH 生效**（宿主半身变更）

## 缺陷
用户点击建议追问（followUps）后，没有针对问题作答，而是跳回该名词的原解释。

## 根因
宿主 `explainImpl` 中，**当带追问的模型解读失败时，静默降级返回词库原解释**——
用户看到的是"点了没反应/跳回原解释"，且不知道模型为何失败（可能：模型服务瞬时错误、
模型解析失败、响应超时等，具体原因此前被吞掉）。

## 修复
1. **不再静默降级**：模型路径失败时返回 `source:'fallback'` + `answered:false` + `note`（含真实原因），
   并附词库基础解释；客户端在解释上方显示**红色警示条**（如"未能用模型回答你的追问（模型解读失败：…）。以下为词库的基础解释。"）。
2. **消息构造规范化**：改用官方 `createUserMessage`（`@deepseek-ai/dsh-llm`）构造用户消息。
3. **错误留痕**：宿主 `console.error` 记录模型错误，便于后续诊断。

## 影响评估
- 改哪端：宿主 `lib/index.js` + 客户端 `lib/client.js` → **本次需重启 DSH 一次**；
- 重启后：点追问 → 成功则显示模型回答；失败则**显示具体原因**（可据此继续精修）。

## 验证（已通过）
- `node --check` 两端语法；
- 冒烟：无追问→词库秒出不变；有追问+模型不可用→`source:'fallback'`、`answered:false`、
  带 note、仍含词库解释与追问；未收录名词+无模型→明确错误。

## 文件变更
- 修改：`plugins/coop-sidebar/lib/index.js`（import createUserMessage、callModel 消息构造、
  explainImpl fallbackNote 显式化、console.error）
- 修改：`plugins/coop-sidebar/lib/client.js`（警示条渲染 + `.coop-warn` 样式）
- 修改：`plugins/coop-sidebar/package.json`（0.2.2 → 0.2.3）

## 重启后用户操作
1. 重启 `dsh web`；
2. 在侧边栏点任意术语 → 点一条建议追问：
   - 若正常 → 看到模型针对该问题的 5 段式回答；
   - 若仍失败 → 解释顶部会出现**红色提示**，请把提示文字发回，据此精修模型调用。
