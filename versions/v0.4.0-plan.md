# v0.4.0 提案 · 术语高亮原文 + 词库可配置

> 状态：📋 提案中（待批准）
> 说明：原 v0.3.0 的「术语高亮」顺延至此（v0.3.0 已交付解释复制/导出）。

## 范围（本迭代）

| # | 功能 | 优先级 |
|---|---|---|
| F1 | **术语点击高亮对话原文**：点击术语时，在对话中定位并高亮包含该术语的文本块 | Must |
| F4 | **词库用户可配置**：在侧边栏内增删词条（落盘到 glossary-extra.json） | Should |

## F1 影响评估（变更三问）

- **改哪端**：客户端为主；但需先调研「根作用域 overlay 如何获取当前会话的对话节点/文本位置」——
  候选：会话作用域标准 props（ConversationSnapshot）或 conversation runtime 服务。**先查契约再写码**（教训 1）。
- **是否需重启**：若仅客户端 → 硬刷新即可；若需宿主配合定位（返回事件 seq）→ 需重启。
- **风险**：高亮不得侵入主对话渲染（遵守"不替换现有 UI"边界），采用 overlay 定位/描边方案。

## F4 影响评估

- 客户端 UI（增删词条表单）+ 宿主 RPC（写 glossary-extra.json）→ 需重启一次。
- 写入需校验词条字段；出错不得破坏既有词库（写临时文件 + 校验后原子替换）。

## 验收标准（草案）

1. F1：点击术语 → 对话中对应文本出现短暂高亮，点击其他区域消失；刷新无残留。
2. F4：侧边栏可新增/删除词条，5 秒内生效；非法输入被拒绝且有提示。
